# 表格内插件（宏）

引擎（`regval`）负责算，宏负责搬：校验与上报都在**信息科自己的那张表**里完成，
不开网页、不另建台账。

本目录当前交付：

| 文件 | 作用 |
|------|------|
| `vba/RegVal.bas` | Excel 加载宏：「校验」「上报」两个按钮 + 底部状态条 + 5 个新列写回 + 样式套用 + 三态反馈 |
| `vba/RegValTokens.bas` | 视觉 token 常量模块（**由引擎生成**，与 `RegVal.bas` 一起导入） |
| `vba/RegValMessages.bas` | 提示文案常量模块（**由引擎生成**，加载态 / 空结果态 / 错误态 / 对话框的话术 + 每个错误码的中文说明） |
| `../macro/wps/regval.js` | WPS JSA 版（后续任务补齐，与 VBA 共用同一份 JSON 契约） |

---

## 1. 宏做了什么

界面就三样东西：**「校验」按钮**、**「上报」按钮**、**底部状态条**。

| 入口 | 干什么 | 引擎调用 |
|------|--------|----------|
| `RegVal_InstallBar` | 装界面：表右侧画两个按钮，数据下面写一条状态条 | 不调用引擎 |
| `RegVal_Validate` | 校验当前表，把 5 个新列写回原表 | `regval validate --input <本表> --out <结果契约 JSON> --state-db <状态库> --error-out <错误报告 JSON>` |
| `RegVal_Push` | 把本批已确认的行推到院内上报网关，回执回填到「上报状态」列 | `regval push --batch <批次> --state-db <状态库> --error-out <错误报告 JSON>` |

「校验」按钮的内部四步：

1. 阻塞调用 `regval validate`（等引擎跑完再读结果）；
2. 读回结果契约 JSON，先过**版本闸门**：`schema_version` 与宏常量不一致 → 提示
   「引擎与宏版本不一致，请升级」并中止，**不做部分写回**；
3. 再过**列名闸门**：契约里的 5 个新列与宏常量逐个比对，不一致同样中止；
4. 把 5 个新列写回原表右侧：列头接在原表已有列之后，数据行逐行写入。

写回只用一次 `Range.Value2` 批量赋值（每 200 行一块），大表不会逐格写回卡顿。
**原表已有列、单元格格式与公式一律不动** —— 宏只写新列那几格。

「上报」按钮的内部三步：

1. 先跑一次「校验」—— 上报按批次走，批次要与当前表里的内容对得上；
2. `regval push --batch <批次>`（写闸门在引擎侧：没人工确认过的行一个字节都不发）；
3. 再跑一次「校验」，把回执驱动的行状态回填到「上报状态」列。

## 2. 底部状态条

状态条写在**数据下面空两行**的那一行，横跨 5 个新列（不碰原表已有列）：

| 时刻 | 状态条上的话 |
|------|--------------|
| 刚装好界面 | `本机校验库：未加载 — 点「校验」开始` |
| 引擎在跑 | `校验中…`（上报时是 `上报中…`） |
| 校验完成 · 有问题 | `已校验 200 行 · 12 项口径问题 · 5 项疑似重复待确认` |
| 校验完成 · 零问题 | `已校验 200 行 · 未发现口径问题` |
| 校验完成 · 没有行 | `表里没有数据行 · 未做校验` |
| 上报完成 | `本批 183 行已提交 · 幂等键见状态库 · 回执已回填` |
| 引擎失败 | `错误码：CONTRACT_VERSION_MISMATCH · 引擎与宏版本不一致，请升级` |

**整句话由引擎算好**（契约 `summary.status_line` / `summary.submission_line`），宏原样显示 ——
宏不自行统计、不自行拼句子，否则表里与终端里会各说一套。终端打的是同一句
（`regval validate` 的第一行输出），两边永远对得上。

### 2.1 三态与提示层级

| 状态 | 状态条 | 还会不会有别的提示 |
|------|--------|--------------------|
| 加载态 | `校验中…` / `上报中…` | 两个按钮置灰（解掉 `OnAction`）、重复点击被 `gBusy` 拦下。宏阻塞执行引擎时界面不刷新，不给这句话用户只会以为卡死 |
| 空结果态 | `已校验 N 行 · 未发现口径问题` | 只有状态条，不弹框 |
| 空结果态（另一种空） | `表里没有数据行 · 未做校验` | 只有状态条，不弹框 |
| 错误态 | `错误码：XXX · 中文说明` | 弹一次对话框（错误码 + 中文说明 + 处理建议）；**不碰单元格**（原表没动过） |

**提示层级**（宏顶部的四个常量写死了这套规矩）：

| 常量 | 值 | 含义 |
|------|-----|------|
| `HINT_RESULT_FILL` | `True` | 结果级问题填单元格（问题行上色） |
| `HINT_RESULT_DIALOG` | `False` | 结果级问题**不弹框** |
| `HINT_ERROR_FILL` | `False` | 阻断级错误不碰单元格 |
| `HINT_ERROR_DIALOG` | `True` | 阻断级错误才弹框 |

同一件事不叠三种提示：结果级 = 填充 + 状态条摘要；阻断级 = 状态条错误行 + 对话框。

### 2.2 文案只有一处

宏里面向用户的中文**一个字都不写死**，全部取自 `vba/RegValMessages.bas`：

```bash
# 重新生成宏用的文案常量模块（改了话术之后跑这条）
regval messages --vba --out macro/vba/RegValMessages.bas

# 导出一份 JSON 清单（给科室看的话术清单用）
regval messages --out messages.json
```

- 错误码的中文说明**只有一处出处**：引擎的 `src/errors.rs`（`ErrorCode::zh()`）。
  生成物里每个错误码一条 `REGVAL_ERR_*` 常量，外加一个查表函数 `RegValErrorText`；
  宏按错误码查表，查不到就原样返回错误码（不吞、不编）。
- 契约测试会逐字比对生成物与引擎源（`tests/ui_states_test.rs`），
  还会扫 `RegVal.bas` 有没有漏写死的中文 —— 改歪了会被测出来。

## 3. 5 个新列的位置

| 列名 | 写在哪 | 取值来源 |
|------|--------|----------|
| 校验结论 | 原表最后一个已有列的右边第 1 列 | 契约 `rows[].conclusion`（通过 / 有提示 / 不通过） |
| 问题类型 | 第 2 列 | 契约 `rows[].issue_types` |
| 问题说明（含依据） | 第 3 列 | 契约 `rows[].issue_detail` |
| 疑似重复项 | 第 4 列 | 契约 `rows[].suspected_duplicate` |
| 上报状态 | 第 5 列 | 契约 `rows[].submission_status` |

重跑一次不会重复堆列：宏先在首行找已有的「校验结论」列，找到就沿用原位置。

## 4. 导入步骤（Excel）

1. 打开 Excel → `文件 → 选项 → 信任中心 → 信任中心设置 → 宏设置`；
2. 选择「**信任对 VBA 工程对象模型的访问**」或把上报表所在目录设为「受信任位置」
   （院内网环境通常由信息科统一加白名单）；
3. `开发工具 → 插入 → 模块`（**建三个模块**），把 `vba/RegVal.bas` 的内容粘进
   第一个模块、`vba/RegValTokens.bas` 粘进第二个、`vba/RegValMessages.bas` 粘进第三个；
4. `Alt+F8` 运行 **`RegVal_InstallBar`** —— 表右侧出现「校验」「上报」两个按钮，
   数据下面出现状态条。（按钮也可以不装：直接运行 `RegVal_Validate` 时宏会顺手补上。）

> **三个模块都要导入**：样式 token（配色、字体、列宽、边框）在 `RegValTokens.bas` 里，
> 提示文案（加载态 / 空结果态 / 错误态 / 错误码中文说明）在 `RegValMessages.bas` 里，
> `RegVal.bas` 只引用它们的常量与函数。少导一个会编译报「变量未定义」。
>
> **粘贴时若报「无效的属性」**：模块文件第一行的 `Attribute VB_Name = "..."` 只在
> `.bas` 文件里合法，粘进 VBE 报错时删掉那一行即可（不影响功能）。

### 4.1 引擎读的是磁盘上的文件

表格有未保存的改动时，宏会先问一句「要现在保存再继续吗」——
引擎读的是磁盘上的文件，未保存的改动它看不到，宏不替用户猜。

### 4.2 编码注意（中文 Windows 会遇到）

`RegVal.bas` 与 `RegValMessages.bas` 以 **UTF-8** 保存（含中文列名与提示文案）。
中文 Windows 的 VBE 按系统 ANSI 代码页（GBK）读模块文件，直接导入可能出现乱码。
两种处理任选其一：

- 导入前把文件另存为 **ANSI/GBK**（记事本「另存为 → 编码 → ANSI」）；
- 或手工把模块里的中文常量替换为现场实际写法。

宏读取契约 JSON 时自己按 UTF-8 解码（`ReadUtf8File`），不依赖系统代码页，
所以**只要模块本身的中文没乱码，写回原表的中文就是对的**。

### 4.3 样式：配色 / 字体 / 列宽从哪来

样式**不写在宏里**。token 的唯一出处是引擎的 `src/ui/tokens.rs`，由引擎生成成
`vba/RegValTokens.bas`：

```bash
# 重新生成宏用的 token 常量模块（改了配色 / 列宽之后跑这条）
regval tokens --vba --out macro/vba/RegValTokens.bas

# 导出一份 JSON 清单（文档、给科室看的配色说明用）
regval tokens --out tokens.json
```

宏里只有 `T_*` 常量与 `RegVal*ForRole` 函数，颜色、字号、列宽、边框都从那儿来；
「问题类型 → 什么颜色」的映射也在生成物里（`RegValRoleForIssueTypes`），
不散落在宏代码里。契约测试会逐字比对生成物与引擎 token，改歪了会被测出来。

写回后套的样式：

| 位置 | 样式 |
|------|------|
| 5 个新列的表头 | 深青灰底 + 白字 + 居中加粗 |
| `校验结论` 列 | 通过=绿 / 有提示=黄 / 不通过=红，加粗 |
| `问题类型` / `问题说明（含依据）` 两列 | 跟着问题类型走：口径问题红、疑似重复黄 |
| `疑似重复项` 列 | 有疑似项才黄底；字用等宽（列里有行键） |
| `上报状态` 列 | 已上报绿 / 被退回橙 / 待重试灰，加粗 |
| 问题行左侧 | 3px 竖色条（口径问题红、疑似重复黄） |
| 底部状态条 | 浅灰底 + 深灰字，横跨 5 个新列 |
| 两个按钮 | 深青灰底 + 白字（表头同一套 token） |

**只碰新列那几格**：原表已有列的单元格值、格式与公式不动。
行高是**行级**属性 —— 新列所在的行会一起变成「标准行高 × 1.3」，
这是视觉目标卡要求的行高；除此之外原表外观不变。

## 5. 导入步骤（WPS）

WPS 侧不是「Excel 宏换个扩展名」—— JSA 的对象模型与 VBA 不同，所以另有一份宏
`wps/regval.js`。但**判定口径只有一处**：契约常量、视觉 token、提示文案三块
都由引擎注入，宏里不写第二套逻辑（计数与状态条句子都从契约 `summary` 段取）。

| 文件 | 是什么 | 怎么改 |
|------|--------|--------|
| `wps/regval.template.js` | 手写模板（逻辑、按钮、写回流程） | 改完跑一次装配命令 |
| `wps/regval.js` | **装配产物**（可直接加载的完整宏） | 不手改 —— 重新生成即可 |

```bash
# 重新生成 WPS 宏（改了模板 / token / 文案之后跑这条）
cargo run -- macro --out macro/wps/regval.js
```

装配产物与模板对不上时测试会红（`提交的wps宏与模板装配结果一致_生成物不漂`），
所以不会出现「模板改了、宏没重新生成」这种漂移。

导入步骤：

1. 确认 `wps/regval.js` 是最新装配出来的；
2. 把这个文件拷到院内机（一个文件即可，不需要别的模块）；
3. WPS 表格里打开上报表 → 开发工具 → JSA 宏 / 加载宏 → 选 `regval.js`；
4. 运行 `RegVal_InstallBar` —— 表右侧出现「校验」「上报」两个按钮，数据下面
   出现状态条。（按钮也可以不装：直接跑 `RegVal_Validate` 时宏会顺手补上。）

部署路径同样改宏顶部的两行常量（`REGVAL_ENGINE_PATH` / `REGVAL_STATE_DB`）：

```javascript
var REGVAL_ENGINE_PATH = "C:\\Program Files\\RegVal\\regval.exe";
var REGVAL_STATE_DB = "C:\\Program Files\\RegVal\\state\\state.db";
```

WPS 侧调引擎走 `Application.Run`、读写文件走 WPS 的 `FileSystem` API；
命令行里的路径同样用引号包住，路径里有空格或中文不会散架。

### 5.1 三条入口同构

| 入口 | 谁用 | 交接面 |
|------|------|--------|
| Excel 加载宏 | 桌面 Excel | 引擎产出的契约 JSON → 宏写回 5 个新列 |
| WPS JSA 宏 | 装了 WPS 的报送机 | 同上（同一份契约、同一套写回） |
| CSV 直跑 | 禁宏的专网报送机 | 引擎产出的契约 JSON → 人工按列粘贴 |

「同构」不是三个入口各写一份代码，而是**一份契约、一种判定**：同一张表从哪条
入口进去，结论、问题数、疑似重复、状态条那句话都得一样。否则信息科拿 WPS
机器校验过的表，到 Excel 机器上看到不一样的结论，就得逐格对账。

这条一致性由 `tests/three_entry_consistency_test.rs` 盯着：同一份样例分别走
CSV 直跑与表格入口，两份契约的业务内容逐字段比对；WPS 侧用宿主替身真跑一遍
宏，核对写回的 5 列与契约逐字段一致、原表一格没动；版本不符时三条入口都拒绝
写回并报同一个错误码。

> **诚实边界**：WPS 侧验证用的是**宿主替身**（`tests/wps_harness/run.js`）——
> 宏逻辑与引擎是真跑的，但宿主不是真的 WPS。真机上的 `Application.Run` 与
> `FileSystem` 行为仍需院内首次导入时人工确认一次。Excel 侧在本轮环境里没有
> Excel，VBA 走的是**同源核对**（两侧常量、读的契约键、按钮、版本闸门、错误码
> 逐项比对），不是执行。

## 6. CSV 直跑降级路径（没有宏环境时）

企业组策略把 VBA/JSA 禁了，或者专网报送机上根本没装 Excel —— 科室改用
**一条命令**：引擎照跑，产出与宏路径**同一份**结果契约，人工按同一列定义
粘回原表。同引擎、同规则、同契约、同判定 —— 不是「另写一份简化版」。

```bash
# 1. 校验（产物是与宏路径同一份契约）
regval validate --input 科室上报表.csv --out 结果契约.json --state-db .regval/state.db

# 2. 看这批读表读成了什么样（编码、分隔符、跳过了几行）
regval status --state-db .regval/state.db
```

### 6.1 列序与写回位置（粘回原表时照这个来）

5 个新列**接在原表最后一个已有列的右边**，列序固定不变：

| 序 | 列名 | 取值来源（契约里的字段） |
|----|------|--------------------------|
| 第 1 列 | 校验结论 | `rows[].conclusion`（通过 / 有提示 / 不通过） |
| 第 2 列 | 问题类型 | `rows[].issue_types`（多类以「、」连接） |
| 第 3 列 | 问题说明（含依据） | `rows[].issue_detail` |
| 第 4 列 | 疑似重复项 | `rows[].suspected_duplicate` |
| 第 5 列 | 上报状态 | `rows[].submission_status`（未上报 / 已上报 / 被退回 / 待重试） |

- **列头**写在原表表头行的这 5 个格子里；**数据行与原表行号一一对应**。
- **被跳过的行（空行 / 重复表头 / 分隔线）在原表里留空，不要往上移** ——
  往上移了，行号就和契约里的 `row_no` 对不上，报给科室的行号会指错行。
  跳过了几行、分别是第几行，看契约 `ingest.skipped_detail` 与终端输出。
- 契约里的 `rows[]` **按原表行序**给出，每行带 `row_no`（原表里的行号，从 1 起，
  不含表头）与 `source_ns`（CSV 取文件主干）—— 按 `row_no` 对回去即可。

### 6.2 读表容错（现场导出的表长这样）

| 脏数据 | 现场来由 | 引擎怎么处理 |
|--------|---------|--------------|
| GBK 编码 | 中文 Windows 的 WPS/Excel「CSV(逗号分隔)」默认存 GBK | 逐行解码；整表 GBK 记 `gbk`，部分行 GBK 记 `mixed` |
| UTF-8 与 GBK 混编 | 多表并入时从不同系统各粘了一段 | 逐行判定：UTF-8 行原样留，GBK 行按 GBK 解 |
| 列名带空格（含全角空格） | 手工整理过的表头 | 表头归一后照样映射到指标编号 / 科室代码等列 |
| 全角逗号分隔 | 从文档或网页里抄出来的表 | 表头里只有全角逗号时，引号外的全角逗号归一成半角 |
| 空行 / 重复表头 / 分隔线 | 导出时留的空行、多表并入时粘进来的表头、分段用的横线 | 不参与校验，但**计数留痕**：行号 + 原因进契约 `ingest` 段，终端照实打一行 |

> **解不出来就报错，不猜**：某一行既不是 UTF-8 也不是 GBK → 报 `INPUT_UNREADABLE`
> 并点名**第几行**，不产出契约文件；整表是 UTF-16 → 明说「本轮只支持 UTF-8 与 GBK」。
> 不拿替换字符糊过去 —— 糊过去的话中文会变成乱码，后面按名称匹配的规则会给出
> 错误的「名称写法不一致」提示。

### 6.3 与宏路径同源

| 入口 | 交接面 |
|------|--------|
| Excel 加载宏 | 引擎产出的契约 JSON → 宏写回 5 个新列 |
| WPS JSA 宏 | 同上（同一份契约、同一套写回） |
| CSV 直跑 | 引擎产出的契约 JSON → 人工按同一列定义粘贴 |

同一张表从哪条入口进去，结论、问题数、疑似重复、状态条那句话、以及
「跳过了几行」都得一样。这条一致性由 `tests/three_entry_consistency_test.rs`
与 `tests/csv_fallback_test.rs` 盯着。

## 7. 改部署路径（必做）

宏顶部的两行常量要按院内实际路径改：

```vba
Public Const REGVAL_ENGINE_PATH As String = "C:\Program Files\RegVal\regval.exe"
Public Const REGVAL_STATE_DB As String = "C:\Program Files\RegVal\state\state.db"
```

命令行里所有路径都用 `Chr$(34)` 包引号，所以**路径里有空格或中文都不会散架**
（如 `D:\院内工具\上报校验\regval.exe`）。

## 8. 目录与权限

| 位置 | 需要什么权限 | 说明 |
|------|--------------|------|
| 引擎二进制所在目录 | 读取 + 执行 | 建议 `C:\Program Files\RegVal\`，普通用户可读即可 |
| 状态库目录（`REGVAL_STATE_DB` 的父目录） | 读 + **写** | 引擎写本机校验库；经办人账号要能建文件 |
| 上报表所在目录 | 读 + **写** | 宏在同目录留一份 `.regval_result.json`（结果契约）与 `.regval_error.json`（错误报告），校验后可手工删除 |
| 宏所在的工作簿 | 无需写权限 | 宏只写新列 |

院内机常见坑：域策略把 `%TEMP%` 或用户目录设成只读 → 状态库写不进去。
把 `REGVAL_STATE_DB` 指到本地磁盘（如 `D:\regval-state\state.db`）比指到用户目录稳。

## 9. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 提示「找不到引擎程序」 | `REGVAL_ENGINE_PATH` 没改或被挪走 | 改宏顶部常量，或参照 `docs/install.md` 重装 |
| 提示「引擎与宏版本不一致，请升级」 | 宏与引擎的契约版本不同 | 换用同一次交付里的宏与引擎二进制 |
| 引擎退出码非 0、原表没动 | 输入表缺必填列 / 库不可写 | 弹窗里给的是错误码 + 中文说明 + 处理建议（从引擎写的错误报告 JSON 里读的）；错误码表见 README「错误与降级」 |
| 结果写在别的表里 | 工作簿有多个工作表 | 宏按契约里的 `source_ns` 逐表写回，不必手工切表 |
| 弹窗问要不要保存 | 表里有未保存的改动 | 引擎读的是磁盘上的文件：先保存再校验，或先取消、改完再点 |
| 状态条写「校验中…」一直不消失 | 引擎被卡住（状态库被别的进程占着） | 看命令行窗口的输出；引擎退出后状态条会自动被结果句覆盖 |
| 按钮点不动 | 上一轮还没跑完（`gBusy` 拦下了重复提交） | 等上一轮结束；窗口底部会提示「上一轮还没跑完，请等它结束再点」 |
| 校验完了但不弹框 | 这是设计：结果级问题用单元格填充 + 状态条摘要说 | 弹框只留给阻断级错误与「表没保存」确认 |
| 提示「变量未定义」 | 三个模块没导全 | `RegVal.bas` + `RegValTokens.bas` + `RegValMessages.bas` 都要导入 |
| WPS 里提示「当前 WPS 版本不支持 Shapes.AddShape」 | 宏的按钮是用形状画的 | 换更新的 WPS 版本；或直接跑 `RegVal_Validate`，按钮装不上不影响校验与写回（宏会记一笔界面异常并如实提示） |
| WPS 里 JSA 宏加载后没反应 | JSA 需要在「开发工具 → JSA 宏」里加载，不是 VBA 编辑器 | 用 `wps/regval.js` 走 JSA 入口；VBA 入口只给 Excel 用 |
