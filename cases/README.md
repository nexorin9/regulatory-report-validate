# 官方口径同构用例集（卫健 27 项指标）

> 这套用例把**国卫办医函〔2021〕28号 附件《病案管理质量控制指标（2021年版）》**的口径，
> 写成一条条能跑的用例：给一行上报表输入，写明期望跑出来的问题（问题类型 / 规则编号 /
> 严重度 / 依据出处），由 `tests/official_cases_test.rs` 逐条断言。

## 这套用例解决什么

口径规则引擎有四类检查器、重复检测有四级漏斗、实体绑定层还有权威键与科室主数据两道核对。
规则改一次，要确认「改完还对」不能靠人肉读 SQL —— 这套用例就是那道保险：
**口径期望写在这里，代码改完跑一遍，用例不绿就不算改对。**

## 怎么跑

```bash
# 只跑这套用例
cargo test --test official_cases_test

# 看某一条用例跑出来的实际问题（失败时断言消息里会打出完整 Issue）
cargo test --test official_cases_test 用例_wj_enum_001 -- --nocapture
```

## 文件与覆盖

| 文件 | 用例数 | 覆盖 |
|------|-------|------|
| `required_missing.json` | 2 | 必填缺失：缺一列、一行缺多列（合并成清单） |
| `enum_bound.json` | 3 | 枚举越界：报告期格式 / 报告期类型 / 指标编号不在册 |
| `unit_mismatch.json` | 2 | 单位不符：两个比率型指标各自写成错单位 |
| `suspected_duplicate.json` | 3 | 疑似重复：表内同键同值 / 跨表同键异值 / 表内同键异值（既提示重复又待人工判定） |
| `boundary.json` | 5 | 边界：分母为 0、单位别名、指标名称别名、跨表疑似重复对、科室代码不存在 |

合计 **15 条用例**，四类口径问题各 ≥2 例，边界例五类齐全 ——
这两条由 `四类口径问题各至少两例且边界例齐全` 一条用例守着。

## 用例格式

```json
{
  "case_id": "wj-enum-001",
  "title": "报告期写成「2026Q3」（不在四种写法之内）",
  "source": "表一",
  "input": { "指标编号": "MER-TL-01", "报告期": "2026Q3", "……": "……" },
  "expect": [
    {
      "rule_id": "R-ENUM-001",
      "issue_kind": "枚举越界",
      "severity": "阻断",
      "message_contains": ["报告期格式", "2026Q3", "期望取值", "2026-H1"]
    }
  ],
  "basis": "官方依据出处（必填，缺依据的用例不允许进用例集）",
  "confidence": "official"
}
```

| 字段 | 含义 |
|------|------|
| `case_id` | 用例编号（一条用例一个 `#[test]`，编号清单在测试文件里） |
| `title` | 中文短句，给人看 |
| `source` / `sources` | 来源表名（多行用例可用 `sources` 逐行指定，如「表一」「表二」） |
| `input` / `rows` | 单行输入 / 多行输入（同一业务记录在几张表里各填一次时用 `rows`） |
| `dept_directory` | 院内 HIS 科室目录（省略 = 目录不可用，科室主数据本轮不核对） |
| `assert_rows` | 断言针对哪几行（行号从 1 起；省略 = 只断言第 1 行） |
| `expect` | 期望问题：`rule_id` / `issue_kind` / `severity` / `missing_columns` / `error_code` / `message_contains` / `issue_count` |
| `expect_pair` | 期望的疑似重复候选对：`level`（`exact` / `normalize`）+ `pair_count` |
| `expect_no_issue` | 该行不应产生任何问题（别名归一那类用例） |
| `basis` | **官方依据出处，必填** —— 没依据的判定没法给科室看 |
| `confidence` | `official` = 官方附件或最小数据格式直接可推；`derived` = 由官方口径推导的边界判定 |

`expect[].issue_count` 默认 1；写 **0** 表示「该规则不应命中本行」
（别名归一那类用例就靠它表达「归一之后是同一个单位，不该报」）。

## 三条纪律

1. **期望值只写在用例文件里。** 测试代码里不另抄一份 —— 抄一份就多一处会漂移的地方，
   口径改了、用例改了，测试里的旧期望还在，两边对不上时谁也不知道该信谁。
2. **用例数与文件条目数必须一致。** `用例数与_cases_文件条目数一致且每条依据非空`
   一条用例守着：少一条用例、多一条用例、id 对不上、某条忘了写依据，都会在它上面失败。
   加用例时记得同步改测试文件里的 `CASE_IDS` 清单与那条 `#[test]`。
3. **案例内容只用卫健口径。** 本轮口径是卫健 27 项指标，
   `案例内容不混入医保结算清单口径` 盯着这件事 —— 案例文件里出现别的域的词，即失败。
