# 重复检测四级漏斗 · 逐级召回率 / 精确率基线

> 「多报一级的漏斗，值不值」—— 这份文档给数字。数字来自一份带人工标注的对照基准集，
> 跑一遍就有，不靠感觉。

## 一句话结论

**前三级（确定性键 → 归一化 → 编辑距离）已经把 7 条真重复标注里的 6 条认了出来
（召回 85.71%），代价是 1 条误报（精确率 85.71%）；第四级（模型语义归并）本轮
未接入模型端点，边际增益**尚未可测** —— 不是「增益为 0」，是「还没测」。**

误报那一条落在**跨院区**：漏斗的比对键（指标编号 + 科室代码 + 报告期 + 业务主键）
**不含机构代码**，两个院区的科室代码撞在一起时会被判成重复。这是本轮实测到的口径边界，
处置见下文「实测发现」。

## 基准集

- 样例：`samples/bench/tables/` 两张脱敏科室表，各 11 行，合计 22 行；只含指标级监管数据，
  **无患者可识别明细**。
- 标注：`samples/bench/labels.json` 11 条成对标注 —— 真重复 7 条、负例 4 条
  （同指标但不是同一件事 3 条、明确不是同一件事 1 条）。
- 每条标注都带判定依据；标注用「来源表 + 行号」定位，装载时解析成行键（定位不到行直接报错）。

## 对比表

```
级,候选数,命中标注,误报,召回率,精确率,本级新增,误报-同指标,误报-明确不是,误报-无标注,说明
L1 确定性键,3,3,0,0.4286,1.0000,3,0,0,0,键与取值完全一致
L2 归一化,6,5,1,0.7143,0.8333,3,1,0,0,写法差异经归一后一致
L3 编辑距离,7,6,1,0.8571,0.8571,1,1,0,0,归一吸收不掉的差异按字符级编辑距离判（阈值 2）
L4 语义归并,7,6,1,0.8571,0.8571,0,1,0,0,本轮未接入模型端点（语义归并的模型调用尚未落地），第四级候选为空
```

口径：**累计**（跑到这一级为止一共报了多少）；召回率 = 命中真重复标注 ÷ 基准集真重复标注总数（7）；
精确率 = 命中真重复标注 ÷ 累计候选对数；**候选里没有标注的对一律算误报**。

## 逐级读法

| 级 | 这一级加进来什么 | 召回变化 | 精确变化 | 值不值 |
|---|---|---|---|---|
| L1 确定性键 | 键与取值完全一致（3 对） | — → 42.86% | — → 100% | 底座：一条都不误报 |
| L2 归一化 | 指标名称别名写法（2 对真 + 1 对误） | 42.86% → 71.43% | 100% → 83.33% | **召回涨 28.6 个点，精确掉 16.7 个点** —— 划算，但要看那 1 条误报是谁 |
| L3 编辑距离 | 名称差 1 个字（1 对真） | 71.43% → 85.71% | 83.33% → 85.71% | **两边都涨** —— 纯增益，留 |
| L4 语义归并 | （本轮未接入） | 85.71% → 85.71% | 85.71% → 85.71% | **尚未可测** |

L3 是三级里唯一一个「召回与精确同时上升」的级别 —— 字符级近似不引入新的误报，
只把原来认不出的近邻认出来。

## 第四级（模型语义归并）的边际增益

**如实写：本轮未接入模型端点，第四级候选为 0 对，召回与精确都没有变化。
这不等于「模型这一级没用」，也不等于「模型这一级有用」—— 是「还没测」。**

- 漏斗编排层已经把第四级接好了（`SemanticCandidateSource` 入口 + 逐级累加 + 逐级可数），
  模型端点落地后只需换一个实现，漏斗编排一行不用改；
- 接线是活的，不是死代码：`tests/dupe_funnel_eval_test.rs` 里用一个**测试替身**
  假装模型认出了那一对写法差异很大的行，第四级随即把它并进候选、召回补到 100%、
  逐级单调性仍成立 —— **这是接线验证，不是模型成绩**；
- 基准集里已经埋好了那一对：`MER-ME-01|0301|2026-Q3|BK-12`，指标编号、业务主键、
  分子分母、填报值全一致，指标名称一个写「CT/MRI检查记录符合率」、另一个写
  「计算机断层与磁共振检查记录符合率」—— 字符编辑距离差了十几个字，四级判据都认不出。
  模型端点接入后重跑 `regval bench`，这一对的去留就是模型这一级的真实成绩。

**留不留模型这一级的判据（等接入后按这个看）**：第四级新增的候选里，
真重复标注占多数就留；误报（尤其新增的跨机构误报）压过真重复就砍掉这一级 ——
漏斗少一级不影响前三级的结论，但少一级意味着那种「写法差异极大」的重复要靠人工自己看出来。

## 实测发现（这一轮量出来的东西，不是设计时就知道的）

### 1. 漏斗的比对键不含机构代码 → 跨院区同科室代码会撞车

误报那一条是：机构代码 `ORG-001` 与 `ORG-002` 的两行，指标编号、科室代码（0301）、
报告期、业务主键、分子分母、填报值全相同 —— 报的是两个院区各自的数，不是同一件事。

- **为什么会撞**：比对键 = 指标编号 + 科室代码 + 报告期 + 业务主键，**机构代码不在里面**；
  实体绑定层的**权威键**含机构代码，所以绑定层判得对（两行分属不同机构，不是重复），
  漏斗却按同一把尺子比，把它们认成一对。
- **为什么先不修**：改比对键要动 L1/L2/L3 的分组语义与既有断言，属于口径变更，
  不能夹在一次基准任务里改。本轮**如实记下来**。
- **处置建议**（下一轮做）：比对键补机构代码，或在漏斗入口按机构代码分桶后再比。
  补进去之后，基准集里这一条误报应当消失，精确率回到 100% —— 这条正好可以当
  修复后的验收用例。

### 2. 同键异值不归漏斗管，是设计如此

基准集里同键异值那一对（97.0 / 97.5）四级都没报，也不该报 —— 它归实体绑定层的
「待人工判定」（同一权威键下取值不同，要人判哪行算数）。这条在基准集里标成
`same_indicator`，作用是**约束**：哪天有人把「同键异值」也算进重复候选，
基准集立刻会把它变成误报，精确率掉下来。

### 3. 业务主键不同即不是同一条记录

手术记录完成率的两行（业务主键 BK-13 / BK-14，取值 80.0 / 75.0）看着像，
但业务主键不同代表两条独立记录。漏斗按业务主键分组比较，天然不碰它们。
这一条是给第四级设的边界：**模型如果不管业务主键、只按名称和取值判，
就会把它判成重复** —— 那就是越界。

## 怎么复现

```bash
export PATH="$HOME/.cargo/bin:$PATH"

# 产出对比表（CSV）
cargo run -- bench --bench-dir samples/bench --out /tmp/dupe-bench.csv

# 机器读版（含结论、漏掉的真重复、边际增益）
cargo run -- bench --bench-dir samples/bench --out /tmp/dupe-bench.json

# 同一份输入跑两次，两个文件逐字相同（对比表里没有时间戳、没有随机数）
shasum -a 256 /tmp/dupe-bench.csv
```

配套测试：`tests/dupe_funnel_eval_test.rs`（13 例：逐级单调不减、逐级数值与标注一致、
标注不合法时报错不静默跳过、两次跑逐字相同、第四级未接入时状态照实报、接线是活的、端到端）。
