> **性质**：结构化视觉目标卡。本轮运行环境**不具备图像生成能力**，因此**不产出概念图、不放占位图**。

> 「概念 / 实测对照」小节并排说明。**不得**用本卡的描述渲染出的示意图冒充实测截图。

## 1. 三个状态

### 起始态（打开模板，还没点「校验」）

- 画面：WPS / Excel 打开「院感专项上报表」模板，A–H 列是科室手填的原表，右侧为空列。
- 底部一条浅灰状态条写着：`本机校验库：未加载 — 点「校验」开始`。
- 视觉重心：用户的注意力落在原表上，系统处于「不打扰」状态。

### 首个可用瞬间（点一次「校验」，数秒内）

- 画面：表右侧多出 **5 列** —— `校验结论` / `问题类型` / `问题说明（含依据）` / `疑似重复项` / `上报状态`。
  - 其中 `问题说明（含依据）` 列承载官方口径依据原文出处，是「为什么不合格、按哪条口径、该怎么改」的落点。
- 着色：12 行浅红底（口径问题）、5 行浅黄底（疑似重复待确认）。
- 状态条变为：`已校验 200 行 · 12 项口径问题 · 5 项疑似重复待确认`。
- 视觉重心：问题行的暖色底 + 左侧 3px 色条最显眼；其次 `上报状态` 列；最后是状态条一行摘要。

### 成形态（点「上报」，回执回填）

- 画面：`上报状态` 列被回执填实 —— 绿底「已上报」/ 橙底「被退回」/ 灰底「待重试」。
- 顶部一行小字：`本批 183 行已提交 · 幂等键见状态库 · 回执已回填`。
- 下月打开同一模板：那 183 行状态列已是「已上报」，只余未上报行可处理。
- 视觉重心：状态列的绿/橙/灰三色，成为下一轮工作的唯一待办清单。

> **口径修正说明**：Phase 1 视觉卡草稿写的是 4 列；按 `spec.md` 的最终最小数据格式，
> 输出列固定为 **5 列**（增列 `问题说明（含依据）`）。本卡与产品实现以 5 列为准。

### 1.1 三态（加载 / 空结果 / 错误）

三个状态条句子在实现里被钉死了（`src/ui/statusbar.rs` 与
`macro/vba/RegValMessages.bas` 同源，逐字一致）：

| 状态 | 状态条上的话 | 视觉重心 |
|------|--------------|----------|
| 加载态 | `校验中…`（上报时 `上报中…`） | 两个按钮置灰（中性灰底 + 深灰字），状态条一行灰底摘要 |
| 空结果态 · 零问题 | `已校验 200 行 · 未发现口径问题` | 5 个新列全是白底（通过=绿字），状态条一行浅灰 |
| 空结果态 · 没有行 | `表里没有数据行 · 未做校验` | 状态条一行浅灰，5 个新列只有表头 |
| 错误态 | `错误码：CONTRACT_VERSION_MISMATCH · 引擎与宏版本不一致，请升级` | 对话框（错误码 + 中文说明 + 处理建议）；状态条同步一行错误摘要 |

**提示层级**（同一件事不叠三种提示）：

- 结果级问题（哪一行不通过 / 疑似重复）→ **单元格填充 + 状态条摘要**，不弹框；
- 阻断级错误（引擎退出码非 0）→ **状态条错误行 + 一次对话框**，不碰单元格。

> **口径修正说明（二）**：Phase 1 草稿的状态条句子带「· 本机库已就绪（可续跑）」，
> 实现里没有这一截 —— 引擎算好的一句成品话以 `src/ui/statusbar.rs` 为准，
> 本卡已对齐；「本机库已就绪」由状态条之外的运行摘要与 `regval status` 承担。

## 2. 画面类型

**桌面窗口**（Excel / WPS 表格窗口内的原表 + 新列 + 底部状态条）。

与本轮锁定的「表格内插件」交付形态一致：**不是**浏览器页面、**不是**终端表格、**不是**服务日志。
三个入口（Excel 加载宏 / WPS JSA 宏 / CSV 直跑）产出同一份 JSON 契约，画面语义一致。

## 3. 视觉语言

### 配色（token 化，见 `src/ui/tokens.rs`）

| 用途 | 底色 | 字色 | token 角色 |
|------|------|------|-----------|
| 原表底 | `#FFFFFF` | `#1F2933` | `surface` |
| 表头 | `#2F3E46` | `#FFFFFF` | `header` |
| 问题行（口径问题） | `#FDE7E9` | `#A3202A` | `issue` |
| 疑似行（疑似重复待确认） | `#FFF4DB` | `#8A6100` | `suspect` |
| 校验通过 | `#E4F3E8` | `#1E6B39` | `passed` |
| 已上报 | `#E4F3E8` | `#1E6B39` | `submitted` |
| 被退回 | `#FBE3D2` | `#9A4A00` | `rejected` |
| 待重试 | `#E8ECF1` | `#4A5A67` | `retry` |
| 底部状态条 | `#F4F6F8` | `#5B6B78` | `statusbar` |
| 表格细线 | `#D5DCE2` | — | `grid` |

> **口径补记**：Phase 1 草稿只列了七种颜色；上面「校验通过」与「被退回」两行是
> Phase 4 落 token 时按本卡三态补齐的 —— 「成形态」一节写明「绿底『已上报』/
> 橙底『被退回』/ 灰底『待重试』」，橙色在本卡配色表里原先没有对应值，
> 落 token 时取浅橙底 `#FBE3D2` + 深橙字 `#9A4A00`。颜色以
> `src/ui/tokens.rs` 的调色板为唯一出处，本表由它对齐。

### 字体族

- 正文：微软雅黑 / PingFang SC，10.5pt（token `body`）。
- 状态列：加粗（`校验结论` 与 `上报状态` 两列）。
- 键值列：等宽 `Consolas`，便于肉眼对齐核对（token `mono`）——
  落地上是「疑似重复项」列（列里有行键）与状态条里的键值摘要。

### 信息层级

1. 问题行（暖色底 + 左侧 3px 色条）—— 最显眼
2. `上报状态` 列 —— 其次
3. 底部状态条一行摘要 —— 最次

### 留白密度

- 列宽紧凑（`问题类型` 约 18 字符宽）。
- 行高 1.3。
- 状态条与表格之间留 8px 呼吸区；不堆辅助按钮。

## 4. 必须可达的约束

以上全部元素仅需 **Excel / WPS 原生能力**即可实现：

- 单元格填充色（`Interior.Color`）
- 字体（`Font.Name` / `Font.Size` / `Font.Bold`）
- 底部状态栏文本（`Application.StatusBar`）
- 单元格批注（`Range.AddComment`）承载 `问题说明（含依据）` 的长文本

**不画**：WebGL / 动画 / 图表特效 / 自定义控件 / 依赖清单里装不下的效果。
本卡中的每个元素都必须在「表格内插件」形态下真做得出，不做纸面设计。
