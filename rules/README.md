# 口径规则目录

本目录放**版本化口径规则表**，由环境变量 `REGVAL_RULE_DIR` 指向（默认 `./rules`）。

规则是**数据**不是代码：规则表由信息科按属地口径文件维护，引擎装载后以命名参数执行，
取值一律走参数，不拼进 SQL 文本。

## 目录里放什么

| 文件 | 说明 |
|---|---|
| `*.rules.json` | 口径规则表（可执行口径：SQL + 命名参数 + 依据 + 版本） |
| `*.seed.json` | 官方指标口径种子（官方 27 项指标的登记，编译成四类检查器的规则） |
| `dupe-distance.json` | 重复检测第三级（编辑距离）的阈值调参（**不是口径**，不参与规则装载） |
| `*.json`（其它名字） | 不装载 |

## 重复检测的阈值（`dupe-distance.json`）

重复检测漏斗第三级用**字符级编辑距离**判「这两个名字像不像同一件事」。
差几个字算像，这个尺度按科室实际情况定 —— 指标名长的科室和短的科室，
合适的阈值不一样，所以阈值是**数据**不是代码：

```json
{
  "threshold": 2,
  "max_length_gap": 40
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `threshold` | 2 | 字符级编辑距离 ≤ 该值才算「疑似重复」。差 1~2 个字算像，差 3 个字以上不算 |
| `max_length_gap` | 40 | 两行指标名称的**长度差**上限。超过就跳过该行对（并计数）—— 差 40 个字还叫同一件事说不通，全量两两比较也会把一次校验拖垮 |

取值顺序（先到先得，后面的不覆盖前面的）：

1. 环境变量 `REGVAL_DUP_DISTANCE_THRESHOLD` / `REGVAL_DUP_MAX_LENGTH_GAP`；
2. 本文件；
3. 内置默认值（阈值 2、长度差上限 40）。

本文件写坏了（不是合法 JSON、阈值不是非负整数）→ **直接报错**，不静默回落默认值 ——
运维以为改了阈值、其实没生效，这种事比报错难查得多。

改完阈值可以看一眼效果：`regval validate` 的终端摘要会打印「距离分布」直方
（每一档距离各有多少对），松紧是否合适一眼看得见。

## 口径种子（`*.seed.json`）

种子是**官方附件的结构化登记**：《病案管理质量控制指标（2021年版）》
（国卫办医函〔2021〕28号 附件，指标一至指标二十七，共 27 项）逐项落成数据。

种子装载后**编译成四条规则**（按指标类别映射到四类检查器）：

| 种子里的什么 | 编译成哪条规则 | 规则参数 |
|---|---|---|
| 类别 = `ratio` 的 24 项 | `R-REQUIRED-002` 条件必填 | `ratio_codes` |
| 全部在册 27 项 | `R-ENUM-004` 指标编号在册 | `indicator_codes` / `indicator_code_values` |
| 写明了单位的 24 项 | `R-UNIT-001` 单位不符 | `expected_units` |
| 比率型指标的精度 | `R-FORMULA-001` 公式不符 | `precision_table` / `ratio_codes` |

**口径以官方种子为准**：同一条规则编号，规则表与种子都有时，版本相同取种子
（官方附件是上游真源），种子版本更低则保留规则表的新版（属地口径改版优先）。
两种情况都记进规则清单，不静默。

### 种子文件格式

```json
{
  "seed_set": "2021.1",
  "source_document": "国卫办医函〔2021〕28号 附件《病案管理质量控制指标（2021年版）》",
  "source_document_file": "mrq_control_2021_病案管理质量控制指标2021年版.pdf",
  "precision_note": "官方附件未逐项写明填报值精度……",
  "indicators": [
    {
      "indicator_code": "MER-TL-01",
      "name": "入院记录24小时内完成率",
      "category": "ratio",
      "official_clause": "指标四",
      "unit": "%",
      "numerator": "入院记录在患者入院24小时内完成的住院患者病历数",
      "denominator": "同期住院患者病历总数",
      "formula": "入院记录24小时内完成率 = … × 100%",
      "precision": null,
      "basis": "国卫办医函〔2021〕28号 附件《病案管理质量控制指标（2021年版）》指标四（MER-TL-01）"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `seed_set` | **是** | 种子集版本标签。缺了报错 —— 种子编译出的规则要带版本号，缺了没法比版本、没法让历史批次按原版本复算 |
| `source_document` | 否 | 官方文件出处 |
| `source_document_file` | 否 | 官方文件（PDF）文件名 |
| `precision_note` | 否 | 填报值精度的处理方式说明 |
| `indicators` | **是** | 逐项种子（按官方指标序号排列） |
| `indicator_code` | **是** | 指标编号（`MER-xx-nn`） |
| `name` | **是** | 指标中文名（官方附件原文） |
| `category` | **是** | 指标类别：`ratio`（比率型）/ `burden`（人均负担型） |
| `official_clause` | 否 | 官方条款号（指标一…指标二十七） |
| `unit` | 否 | 计量单位。`null` = 官方附件未写明 → **口径待补，不推断** |
| `numerator` / `denominator` | 否 | 计算公式的分子 / 分母口径（官方附件原文） |
| `formula` | 否 | 计算公式（官方附件原文整理成一行） |
| `precision` | 否 | 填报值精度（小数位数）。`null` = 官方未写明 → 按默认 1 位比对，标口径待补 |
| `basis` | **是** | 官方依据出处。空串视为缺失 → **口径待补**，不猜、不进编译参数 |

字段名写错（多写、拼错）会**直接报错**，不会被静默忽略。

### 口径待补

官方附件没有逐项写计量单位，也没有逐项写填报值保留几位小数。本产品的处理是
**不猜**：

| 缺什么 | 处理 | 在清单里 |
|---|---|---|
| `unit` 为 `null`（`MER-HR-01…03`） | 标「口径待补」，**不判**这三项的单位是否匹配，不进期望单位表 | 「口径待补」逐条点名 |
| `basis` 为空 | 标「口径待补」，不进在册编号清单、不进期望单位表 | 「口径待补」逐条点名 + 「依据缺失」计数 |
| `precision` 为 `null`（27 项全部） | 按默认小数点后 1 位比对（容差为末位的一半） | 「按默认精度比对 27 项」计数 |

猜出来的单位会让科室按错口径填数，比「没写」更糟 —— 所以宁可标待补。

```bash
regval rules --dir ./rules     # 终端可见：口径待补逐条列出
```

## 规则表文件格式

```json
{
  "rule_set": "2021.1",
  "rules": [
    {
      "rule_id": "R-REQUIRED-001",
      "indicator_code": null,
      "rule_kind": "required",
      "sql_lines": [
        "SELECT row_uid AS row_uid, :label_1 AS missing_column",
        "  FROM rows",
        " WHERE batch_ref = :batch_ref"
      ],
      "params": { "scope": null, "label_1": "指标编号" },
      "basis": "国卫办医函〔2021〕28号 附件《病案管理质量控制指标（2021年版）》",
      "version": "2021.1",
      "severity": "blocking",
      "effective_from": null
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `rule_set` | 否 | 这张表声明的口径版本标签；缺省不猜 |
| `rules` | 是 | 规则清单 |
| `rule_id` | 是 | 规则编号（问题清单与举证包按此回溯） |
| `indicator_code` | 否 | 适用指标编号；缺省或 `null` 表示适用于全部指标 |
| `check_column` | 否 | 检查项：同一检查类型下的不同检查项（如枚举越界下的 `reporting_period` / `period_type` / `unit` / `indicator_code`）。**同一检查类型下的多条规则必须各写各的检查项**，否则换版时会互相顶掉 |
| `rule_kind` | 是 | 检查类型代号：`required`（五列必填）/ `required_conditional`（比率型指标条件必填）/ `enum`（枚举越界）/ `unit`（单位不符）/ `formula`（公式不符）/ `duplicate`（疑似重复） |
| `sql_lines` 或 `sql` | 是 | 规则 SQL。`sql_lines` 按行给（便于手工维护），`sql` 整段给；两者只能给一个 |
| `params` | 否 | 命名参数（字符串 / 整数 / null） |
| `basis` | **是** | 官方依据出处。**留空则该规则拒绝装载** —— 没有出处的口径问题没法向科室解释 |
| `version` | 是 | 规则版本号（换版用，如 `2021.1` / `2022.1`） |
| `severity` | 是 | 严重度代号：`blocking`（阻断）/ `hint`（提示） |
| `effective_from` | 否 | 生效日期（换版闸门在后续任务落地，本版只记录） |

字段名写错（多写、拼错）会**直接报错**，不会被静默忽略 —— 口径文件是手工维护的，
「看起来配了、其实没生效」比报错难查得多。

## 换版流程

属地口径文件改版时，**新增**一张版本号更高的规则表即可，旧表**不要删**：

```
rules/
├── rules-2021.1.rules.json   ← 旧版，装载后标「已被取代」，保留可追
└── rules-2022.1.rules.json   ← 新版，生效
```

装载时的归并规则：

- **口径槽位** = (检查类型, 适用指标, 检查项)。同一槽位内**版本号最高的一条生效**；
  检查类型按口径范围细分：`required`（五列必填，适用全部指标）与
  `required_conditional`（条件必填，只适用比率型指标）是**两个槽位** ——
  否则换版时新口径会把旧口径顶掉；同一检查类型下的多条规则（如四条枚举越界）
  靠**检查项**再分槽位，否则换一版「报告期格式」的口径会把另外三条一起顶掉；
- 其余版本标为「已被取代」，**保留可追**（不物理删除）—— 历史批次据此按原版本复算；
- 同一槽位出现**两条同版本**规则是口径歧义，直接报错，不二选一；
- 版本号比较：`2021.2` > `2021.1` > `v1`，纯数字段按数值比。

换版需要质控岗确认、要看新旧口径差异清单的那部分（换版闸门与差异标注）在后续版本提供。

## 当前十一条口径管什么

| 规则 | 检查类型 | 检查项 | 严重度 | 管什么 |
|---|---|---|---|---|
| `R-REQUIRED-001` | 必填缺失 | — | 阻断 | 指标编号 / 指标名称 / 科室代码 / 报告期 / 业务主键 —— 任何一行都必填 |
| `R-REQUIRED-002` | 条件必填缺失 | — | 阻断 | 比率型指标（官方 24 项率指标）的 分子 / 分母 / 填报值 / 计量单位 |
| `R-UNIQUE-001` | 疑似重复 | — | 提示 | 同一来源表内业务主键撞键；只标疑似，交重复检测漏斗判定，不合并、不上报 |
| `R-ENUM-001` | 枚举越界 | `reporting_period` | 阻断 | 报告期写法：只认 `2026` / `2026-H1` / `2026-Q1…Q4` / `2026-M01…M12` |
| `R-ENUM-002` | 枚举越界 | `period_type` | 阻断 | 报告期类型（可选列）：只认 年报 / 半年报 / 季报 / 月报 / 实时报 |
| `R-ENUM-003` | 枚举越界 | `unit` | 阻断 | 计量单位取值：只认 例 / 例次 / 人次 / 人 / % |
| `R-ENUM-004` | 枚举越界 | `indicator_code` | 阻断 | 指标编号必须在官方 27 项之内（编号不在册 → 判不出指标类别，不套条件必填） |
| `R-UNIT-001` | 单位不符 | `unit` | 阻断 | 单位必须是该指标的口径单位（24 项比率型指标固定为 `%`；`MER-HR-01…03` 口径待补，不判） |
| `R-FORMULA-001` | 公式不符 | `value` | 阻断 | 填报值按官方公式「分子 ÷ 分母 × 100%」复算，对不上就报并给出期望取值 |
| `R-FORMULA-002` | 数据形态错误 | `denominator` | 阻断 | 分母为 0（`DENOMINATOR_ZERO`）—— 不静默当 0，也不报成公式不符 |
| `R-FORMULA-003` | 数据形态错误 | `numeric` | 阻断 | 分子 / 分母 / 填报值非数值或为负（`INVALID_NUMERIC`）—— 与「公式不符」分开归类 |

第五条枚举维度「科室代码」是**目录型枚举**：不在 SQL 规则里，由院内 HIS 科室目录核对
（`GET {HIS_BASE_URL}/api/v1/dept-directory`），匹配不到报「科室主数据不一致」
（错误码 `DEPT_NOT_FOUND`）；目录拉不到时跳过并标「科室主数据未校验」，**不静默通过**。

枚举越界的问题说明一定带**期望取值清单**（科室照着改，不用猜该改成什么）。

### 报告期类型列

「报告期类型」是**可选列**：表里有这一列才校验，没有就不报（不猜）。可接受的表头写法：
`报告期类型` / `报表类型` / `上报类型` / `报告类型`。取值必须是
年报 / 半年报 / 季报 / 月报 / 实时报 之一。

### 空值口径（改规则表时按这张表对齐）

| 单元格里的东西 | 判定 | 理由 |
|---|---|---|
| 空串 / 纯空白（含全角空格、不间断空格、Tab） | **缺失** | 等同没填 |
| `NaN` | **缺失** | 官方口径里没有这个取值，它不是填报结果 |
| `0` | **不是缺失** | 0 是有效填报值（本期零事件）；「分母为 0」另有错误码 `DENOMINATOR_ZERO` |
| 非数值原文（如 `abc`） | **不是缺失** | 单元格填了，是**格式错误**，由公式复算检查器报 `INVALID_NUMERIC` |

判定用「这一列有没有值」，**不用 0 顶替空值** —— 空就是空。

`regval validate` 用的是同一套装载逻辑（严格模式）：**目录里有规则被拒绝装载就直接报错**，
不会静默少跑一条口径。结果契约的 `rule_status` 段里带着本次用的规则集版本与指纹 ——
「这批结论按哪套口径算的」有据可查。

## 兜底口径表

`REGVAL_RULE_DIR` **未配置**时，引擎用内置兜底口径表（与本目录的
`rules-2021.1.rules.json` 内容一致，版本号同为 `2021.1`）。口径不因「从哪装载」而变 ——
两种装载路径的结论逐条相同，`tests/rules_loader_test.rs` 对此有断言。
