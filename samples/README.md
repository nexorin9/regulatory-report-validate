# 样例数据（脱敏合成集）

> 真实院内行级数据拿不到，所以样例由 `samples/generate.py` **脚本化合成**：
> 固定随机种子、同一份种子两次生成字节完全一致、不联网、不依赖任何外部数据集。

## 这套数据是什么

- `dataset/` —— **基线样例集**：6 张科室专项上报表 × 200 行 = **1200 行**，
  外加一张 `合并表.csv`（6 张表并进同一个模板后的样子，1200 行）与一份
  `dept_directory.json`（样例科室目录，格式与院内 HIS 目录接口的响应一致）。
- `dataset-scale/` —— **规模样例集**：10 张科室表 × 500 行 = **5000 行**，
  给性能基准用（耗时、内存、大批量正确性）。
- 每套目录里都有 `manifest.json`：逐文件的 sha256、行数、编码，以及**埋点条数**
  （不是估的，是生成器数出来的）。

数据只到**指标级监管数据**（指标编号、指标名称、科室、报告期、分子分母、填报值、
计量单位、业务主键）。**没有患者可识别明细** —— 没有姓名、身份证、住院号、
病案号、性别、年龄、联系方式、床位号。机构代码用 `ORG-001` / `ORG-002`，
业务主键一律 `BK-` 前缀，一眼能看出是合成数据。

指标编号与指标名称取自《病案管理质量控制指标（2021年版）》（国卫办医函〔2021〕28号
附件）的**真实 27 项指标编号与名称**；科室代码、分子、分母、填报值、业务主键
全是合成样例值。

## 怎么生成

```bash
cd <项目根>

# 生成两套（默认写到 samples/dataset/ 与 samples/dataset-scale/）
python3 samples/generate.py

# 只生成其中一套
python3 samples/generate.py --only baseline
python3 samples/generate.py --only scale

# 换输出目录 / 换种子
python3 samples/generate.py --out-dir /tmp/regval-samples
python3 samples/generate.py --seed 20261107
```

生成器**只用 Python 标准库**：不联网、不下载数据集、不依赖任何外部数据源。
断网可用。

## 怎么验证

```bash
# 1. 同一份种子生成两次，字节逐字相同（不落盘）
python3 samples/generate.py --self-test
# → [OK] 同一份种子（20261107）生成两次，22 个文件逐字节相同

# 2. 按清单里的 sha256 与行数复核已落盘的文件（不重写）
python3 samples/generate.py --check
# → [OK] 已落盘的样例文件与清单一致（sha256 与行数都对得上）

# 3. 手工对一遍 sha256（清单 → 实际文件）
python3 - <<'PY'
import hashlib, json, pathlib
m = json.load(open('samples/dataset/manifest.json'))
for t in m['tables']:
    d = hashlib.sha256(pathlib.Path('samples/dataset', t['file']).read_bytes()).hexdigest()
    print(('OK  ' if d == t['sha256'] else 'BAD '), t['file'], d[:16])
PY

# 4. 样例里不含患者可识别字段名（退出码 1 = 一个都没命中）
grep -nE '姓名|身份证|住院号|病案号|证件号|手机|电话|银行卡|就诊号|床号|年龄|性别' \
  samples/dataset/*.csv samples/dataset-scale/*.csv

# 5. 行数符合预期
for f in samples/dataset/*.csv; do echo "$f $(($(wc -l < "$f") - 1)) 行"; done
```

## 拿它跑产品

```bash
# 一张表（CSV 直跑入口）
REGVAL_STATE_DB=/tmp/regval-demo.db ./target/debug/regval validate \
  --input samples/dataset/病案统计室表.csv --out /tmp/契约.json

# 六张表并进模板（信息科现场的操作形态，也是跨表重复能露出来的形态）
REGVAL_STATE_DB=/tmp/regval-demo.db ./target/debug/regval validate \
  --input samples/dataset/合并表.csv --out /tmp/契约.json
```

基线合并表的实测结果（种子 20261107）：

| 指标 | 实测值 |
|---|---|
| 读入行数 | 1200 行（0 空行、0 跳过） |
| 读表编码 | `mixed` —— 医技部表那张是 GBK/UTF-8 混编 |
| 口径问题 | 336 项，涉及 240 行 |
| 疑似重复 | 48 对（确定性键 12 · 归一化 12 · 编辑距离 24），另有 96 行因同键异值标「待人工判定」 |
| 耗时 | 约 1.4 秒（单机、未配模型端点） |

## 埋了什么（脏数据形态）

| 埋点 | 条数（基线 1200 行） | 用意 |
|---|---|---|
| 必填缺失 | 25 | 指标名称 / 业务主键 / 科室代码 / 报告期留空 |
| 必填缺失（纯空白值） | 8 | 全角空格与半角空格也算缺失，不做「空串才算」的宽松处理 |
| 枚举越界（报告期格式） | 8 | `2026Q3`、`2026-M13`、`2026 年第三季度` 等非法写法 |
| 枚举越界（报告期类型） | 10 | `季度报`、`半年` 等非法取值 |
| 枚举越界（计量单位） | 8 | `台`、`个`、`床日` |
| 枚举越界（指标编号不在册） | 7 | `MER-XX-99`、`MER-TL-09` |
| 单位不符 | 16 | 比率型指标的单位写成 `例` / `例次` |
| 单位别名 | 36 | `％` / `﹪` / `百分比` / `例数` / `例次数` / `人次数` / `人数` |
| 指标名称别名 | 9 | `CT、MRI检查记录符合率`、`出院病历2日归档率`、`入院记录24H内完成率` 等 |
| 疑似重复 · 确定性键（L1） | 12 | 同一业务主键，取值逐字一致 |
| 疑似重复 · 归一化候选（L2） | 12 | 同一业务主键，指标名称写法不同但归一后一致 |
| 疑似重复 · 编辑距离候选（L3） | 24 | 同一业务主键，指标名称差 1 个字 |
| 待人工判定（同键异值） | 12 | 同一业务主键但取值不同 —— 不算重复，归实体绑定层判 |
| 公式不符 | 35 | 分子分母与填报值对不上 |
| 分母为零 | 8 | 归 `DENOMINATOR_ZERO`，不当成公式不符 |
| 非数值 | 7 | 分子写成 `abc` / `N/A` / `—` / `约120` |
| 科室代码不在目录 | 11 | `0999`、`0888` —— 触发「科室主数据不一致」 |
| 科室名称写法不一致 | 16 | 科室代码对得上、名字对不上 —— 只提示，不阻断 |
| 生僻字 | 17 | 备注里的生僻字（淼/焱/燚/犇/骉/赑/灥/龘/髹/昶），验「按字符不按字节处理」 |
| 首尾全角空白 | 7 | 科室名称前后带全角空格 —— 归一化路径 |
| 首尾半角空白 | 6 | 备注前后带半角空格 |
| GBK 混编行（医技部表） | 40 | 医技部表按 GBK/UTF-8 混编写盘：中文 Windows 导出 CSV 的常见形态 |

规模集（5000 行）的埋点条数见 `samples/dataset-scale/manifest.json` 的 `defects` 段，
比例与基线集一致（每表 200→500 行，埋点按行数等比放大）。

## 边界

- 本目录属于**测试数据层**，不是产品的最终对接方式。真实院内数据要从 HIS /
  报表系统导出后走 `regval validate --input <表>` 进产品；这里的合成数据只用来
  把规则、漏斗、状态机和性能基准**跑起来、看清楚**。
- 数据**全部为合成数据**，不来自任何真实医院，不含患者可识别明细。
  指标编号与指标名称引用的是公开发布的官方指标名称，仅为对齐口径。
- `dept_directory.json` 是**协议替身**，格式与 HIS 目录接口的响应一致；
  真实的科室主数据要从 `GET {HIS_BASE_URL}/api/v1/dept-directory` 取，
  凭据走环境变量（`HIS_BASE_URL` / `HIS_API_TOKEN`）。
